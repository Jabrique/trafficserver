# URI Signing Python Tool - Examples

This document provides practical examples for using the Python URI signer tool with Auth Level 1 and Auth Level 2 configurations.

## Basic Usage (Auth Level 1)

### Generate a Simple Signed URL

```bash
./uri_signer.py -c example_config.json -u "https://cdn.example.com/video.mp4"
```

This generates a URL with a JWT token embedded as a query parameter:
```
https://cdn.example.com/video.mp4?URISigningPackage=eyJhbGc...
```

### Specify a Particular Key

```bash
./uri_signer.py -c example_config.json -u "https://cdn.example.com/video.mp4" --key_index 2
```

### Custom Token Lifetime

```bash
./uri_signer.py -c example_config.json -u "https://cdn.example.com/video.mp4" --token_lifetime 600
```

## Auth Level 2: Two-Token Authentication

Auth Level 2 implements a two-token system:
- **Access Token**: Short-lived (5-15 minutes), embedded in URL, includes device binding salt
- **Renewal Token**: Long-lived (hours/days), set as cookie, used to generate new access tokens

### Generating Access Tokens with Device Binding

Access tokens should include `cdnisalt` claim for device binding:

```bash
# Generate access token with salt (SHA256 hex of client fingerprint)
./uri_signer.py \
  -c auth_level2_access_token.json \
  -u "https://cdn.example.com/playlist.m3u8" \
  --cdnisalt "a3f5b2c1d4e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2" \
  --cdniuc "uri-regex:https://cdn.example.com/video/*" \
  --token_lifetime 300
```

**Important**: The salt value should be computed on the origin server using the same algorithm as the CDN (SHA256 of session ID + optional user agent + client IP).

### Salt Generation Example (Python)

```python
import hashlib

def generate_salt(session_id, user_agent=None, client_ip=None):
    """Generate device binding salt matching C implementation"""
    components = [session_id]
    if user_agent:
        components.append(user_agent)
    if client_ip:
        components.append(client_ip)

    concat = ''.join(components)
    hash_obj = hashlib.sha256(concat.encode('utf-8'))
    return hash_obj.hexdigest()

# Example usage
session_id = "abc123-player-session"
user_agent = "Mozilla/5.0 ..."
salt = generate_salt(session_id, user_agent)
print(f"Salt: {salt}")
```

### Renewal Token Configuration

Renewal tokens are automatically generated by Traffic Server when:
1. The access token includes `cdnistt: 1` (signed token transport enabled)
2. The access token validates successfully
3. Renewal token configuration is enabled in the ATS config

The renewal token will be set as a cookie by Traffic Server and includes the same `cdnisalt` for validation on subsequent requests.

## Custom Package Names

For systems using custom parameter names:

```bash
# The default access token parameter name is "cr-access-token"
# The default renewal token parameter name is "cr-session-token"

# Example with explicit parameter name:
./uri_signer.py \
  -c auth_level2_access_token.json \
  -u "https://cdn.example.com/segment001.ts" \
  --package_name "cr-access-token" \
  --cdnisalt "..." \
  --token_lifetime 300
```

## Manifest Token Injection

When Auth Level 2 manifest injection is enabled, Traffic Server automatically:
1. Detects HLS/DASH manifest responses
2. Injects the renewal token into all segment URLs
3. Returns modified manifest to client

Example workflow:
```bash
# 1. Origin generates access token for master playlist request
./uri_signer.py \
  -c auth_level2_access_token.json \
  -u "https://cdn.example.com/master.m3u8" \
  --cdnisalt "$(calculate_salt)" \
  --cdniuc "uri-regex:https://cdn.example.com/*" \
  --token_lifetime 300

# Client receives URL: https://cdn.example.com/master.m3u8?cr-access-token=eyJ...

# 2. Client requests master playlist
# 3. ATS validates access token, generates renewal token, sets cookie
# 4. ATS transforms manifest, injecting renewal token into all segment URLs
# 5. Client receives manifest with URLs like:
#    https://cdn.example.com/segment001.ts?cr-session-token=eyJ...
```

## Configuration Examples

### Access Token Configuration (auth_level2_access_token.json)

```json
{
  "iss": "CDN Provider",
  "token_lifetime": 300,
  "aud": "Apache Traffic Server",
  "cdnistt": true,
  "cdniets": 3600,
  "cdnistd": 2,
  "keys": [
    {
      "alg": "HS256",
      "kid": "access-key-1",
      "kty": "oct",
      "k": "YourBase64EncodedAccessTokenSecretKey1"
    }
  ]
}
```

**Configuration Fields**:
- `token_lifetime`: 300 seconds (5 minutes) for short-lived access tokens
- `cdnistt: true`: Enable renewal token generation
- `cdniets: 3600`: Renewal tokens valid for 1 hour
- `cdnistd: 2`: Renewal cookie path includes 2 path segments

Corresponding ATS plugin config (`uri_signing.config`):

## Security Best Practices

1. **Salt Generation**:
   - Always use the same headers configured in ATS
   - Use cryptographically secure session IDs
   - Compute salt on trusted origin server, never client-side

2. **Token Lifetimes**:
   - Access tokens: 5-15 minutes (balance security vs. user experience)
   - Renewal tokens: 1-24 hours (matches typical session durations)

3. **Key Management**:
   - Use different keys for access tokens vs. renewal tokens
   - Rotate keys regularly
   - Store keys securely (never commit real keys to version control)

4. **URI Container Patterns**:
   - Use specific patterns: `uri-regex:https://cdn.example.com/authorized-path/*`
   - Avoid overly broad patterns like `uri-regex:*`

## Troubleshooting

### Token Validation Failures

1. **403 Forbidden**: Check token expiry, signature, and issuer match ATS config
2. **Salt validation failure**: Ensure salt generation algorithm matches exactly
3. **cdniuc mismatch**: Verify URI pattern in token matches requested URI

### Debug Mode

Enable ATS debug logging:
```bash
traffic_ctl config set proxy.config.diags.debug.enabled 1
traffic_ctl config set proxy.config.diags.debug.tags uri_signing
tail -f /var/log/trafficserver/diags.log | grep uri_signing
```
